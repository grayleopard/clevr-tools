## Containment guardrails: verified, but do not relax

These are not reopened as P2 feature work. They are release boundaries that Smart Converter and file flows must preserve:

- HEIC remains contained: the direct route renders only a disabled status notice (`app/convert/heic-to-jpg/page.tsx:34-48`), its Smart Converter contract has no actions (`lib/image-remediation/smart-converter-contracts.ts:60`), and both initial and deferred inputs omit HEIC/HEIF (`components/home/SmartConverter.tsx:748-762`, `components/home/SmartConverterDeferred.tsx:237-254`). The dormant decoder has a 15-second UI timeout, but cannot cancel underlying `heic2any` work (`lib/processors.ts:131-161`, `lib/image-remediation/heic-validation.ts:92-109`). Relaunch requires the representative orientation/color/metadata/browser corpus stated in the notice.
- Legacy DOC is correctly excluded by Smart Converter (`tests/p1-files-images.test.mjs:164-190`), even though direct Word-to-PDF acceptance must be corrected under FILE-P2-11.
- The current contract table exposes only live destinations; the static check verifies this at `tests/p1-files-images.test.mjs:108-160`. Retain that hard gate while replacing its manual duplicated map with executable capability metadata.
- Prior P1 image fixes should not be regressed: Resizer now validates actual static raster format and rejects GIF (`components/tools/ImageResizer.tsx:108-155,279-303`); Cropper rejects GIF and validates circle PNG output (`components/tools/ImageCropper.tsx:84-127,194-259`); parsed browser assertions cover those behaviors at `tests/e2e/tool-audit/file-artifact-audit.spec.ts:211-270`.

## Recommended order of work

1. **Keep containment intact and repair FILE-P2-01 first.** It is the only currently evidenced parsed browser-output failure in this scope.
2. **Create one intake/output reliability layer (FILE-P2-02, -03, -07, -08).** It should own input classification, limits, encrypted/corrupt errors, generated-artifact checks, and handoff parity rather than duplicating inconsistent checks in components.
3. **Make operations lifecycle-safe (FILE-P2-06, -10, -12).** Add URL ownership, run tokens, cancel/destroy, and timer cleanup before expanding large-file support.
4. **Make batches reproducible (FILE-P2-05) and close the real conversion coverage gaps (FILE-P2-09, -11).** Parse downloaded ZIP/PDF/image artifacts; URL navigation alone is not an acceptance criterion.

## Acceptance floor for closure

A record may close only when its direct and Smart Converter handoff paths have deterministic browser evidence, emitted artifacts are independently signature/parse checked, replacement/reset/cancel/unmount behavior is exercised, and the tested format boundary (including filenames, order, alpha/orientation where relevant, password/corruption for PDFs) is explicitly recorded. A visible success state, output URL, or route change alone is insufficient.
